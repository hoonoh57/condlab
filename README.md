\## 2. 핵심 로직: 60일 이동평균 돌파의 정확한 기준가



이 프로젝트에서 가장 중요한 확정 사항이다.



\### 문제

일봉 60이평 돌파를 실시간(분봉)에서 판정하려 할 때,

차트에 표시되는 60이평값(예: 44,982)을 기준선으로 쓰면 틀린다.

그 값은 \*\*오늘 종가(=현재가)를 이미 표본에 포함한 사후값\*\*이기 때문에,

주가가 오르면 이평선도 같이 따라 올라간다.



\### 해결 (수학적 도출)

어제까지의 종가 59개 합을 `S`, 현재가를 `P`라 하면 돌파 조건은



&#x20;   P > (S + P) / 60   ⟺   60P > S + P   ⟺   59P > S   ⟺   P > S / 59



즉 \*\*실시간 돌파 기준가 = 직전 59일 종가의 평균(`base59`)\*\* 이고,

이 값은 \*\*장중에 변하지 않는 상수\*\*다.



검증 예 (두산퓨얼셀 336260, 2026-09-07):

\- 차트 60이평 = 44,982 / 현재가 = 50,400

\- S = 60 × 44,982 − 50,400 = 2,648,520

\- base59 = 2,648,520 ÷ 59 = \*\*44,890\*\* ← 실제 돌파선

\- 차이 92원 = 현재가가 스스로 이평을 끌어올린 몫



\### 상태 조건 vs 사건 조건

`c > base59` 만 쓰면 "어제도 위였고 오늘 급락 중이지만 아직 위인" 종목까지

전부 참이 된다(상태 조건). 양봉 초입 포착에는 \*\*전일 미돌파 조건\*\*이 필수다.



&#x20;   prev\_c < prev\_ma60   -- 어제 종가는 어제 60이평 아래  (사건화)

&#x20;   AND c > base59       -- 오늘 처음 위로 올라옴



\### 분봉 이평으로는 환산할 수 없다

일봉 60이평을 240분봉 480/640 이평 등으로 근사하려 시도했으나 \*\*실패\*\*.

\- 이평 기간은 "일수"가 아니라 "봉 개수"이므로 배수 환산이 필요하지만,

\- 대상 종목이 급등락 이력을 가지면 기간에 따라 값이 단조롭지 않아

&#x20; (120→37,500 / 480→48,755 / 640→44,758) 우연히 맞는 기간이 여러 개 존재한다.

\- 근본적으로 일봉 이평은 하루 1개 표본, 분봉 이평은 장중 마감값까지 섞으므로

&#x20; 표본 구성 자체가 달라 동일해질 수 없다.



\*\*결론: 분봉 차트에는 `base59` 상수를 수평선(가격선)으로 그어 쓴다.\*\*

&#x20; AND sec\_class = 'COMMON'             -- 우선주 제외

STEP 6 — 분봉 신호 시각 판정

후보를 일봉으로 먼저 좁힌 뒤 해당 날짜 파티션만 읽는다. 당일 고가로 프루닝해도 신호 유실 없음(close > base59 ⟹ high > base59). 첫 돌파 시각은 MIN(ts) WHERE c > base59 — 윈도우 함수 불필요.



STEP 7 — 백테스트

기준일 D 신호 → D+1 첫 봉 진입 → 손절/목표/추적손절/종가청산 중 가장 이른 사건으로 청산. 전부 MIN(CASE WHEN ...) 패턴으로 루프 없이 계산. MFE/MAE 동시 산출. 추적손절은 LAG(peak)를 써야 함 (같은 봉의 고가로 만든 추적선을 같은 봉 저가가 때렸다고 하면 봉내 미래 참조).



STEP 8 — 박제

cond\_def / cond\_run / cond\_hit에 적재. cond\_run에 실행 시점의 일봉·분봉 최종일을 반드시 남긴다 (나중에 결과가 달라졌을 때 로직 변경인지 데이터 증가인지 구분하는 유일한 단서). sql\_text는 DB에만 두지 말고 .sql 파일로도 내려 git 관리.

백테스트 현실성



봉 내부 경로를 알 수 없어 손절·목표 동시 접촉은 가정일 뿐. 손절 우선(보수적)으로 두되, 반대 가정으로도 돌려 민감도를 확인할 것.

상한가 매수 불가, VI 발동 구간 단일가 체결 등은 분봉만으로 판별 불가.

참여율 제한(해당 봉 거래량의 일정 비율 이내) 없으면 저유동성 종목에서 비현실적 수익이 나온다.

수수료·세율·호가단위는 제도 변경 대상. 파라미터로 두고 현재 값 확인 필요.

장중 신호는 종가 확정 전략과 다른 전략이다. 15:30에 기준가 아래로 밀리면 무효 → 유지율을 먼저 측정할 것.

과최적화 파라미터 조합을 수백 개 돌려 최적값을 찾으면 과최적화가 거의 확실하다. 기간을 앞뒤로 분할해 한쪽에서 정한 파라미터를 다른 쪽에서 검증하는 절차를 처음부터 넣을 것.

한 단계씩: 코드 하나 실행 → 에러 없음 확인 → 다음. 미리 쌓지 않는다.

환경 먼저: 대량 작업 전 버퍼풀/RAM/디스크/행 수를 먼저 확인한다. 세션 1의 40분 낭비는 이 순서를 건너뛴 결과다.

소규모 실측 후 확장: 종목 30개로 시간을 재고 그 값으로 분할 크기를 정한다. 예상보다 오래 걸리면 그 자체가 설계 오류 신호.

원본 불변: market\_data는 SELECT만. 계정 권한 분리 권장 (market\_data SELECT only / condition\_lab ALL).

긴 트랜잭션 회피: 수십 분 조회는 undo 이력을 붙잡아 서버 전체를 느리게 만든다. 기간을 잘라 짧게 여러 번.

11\. 면책

이 문서와 코드는 지표 계산 및 조건식 검증 방법에 관한 기술 자료다. 특정 종목의 매매를 권유하지 않으며, 과거 검증 결과가 미래 성과를 보장하지 않는다. 위 포착 목록은 조건식 동작 확인용 예시일 뿐이다.

## 성과검증 이력 (키움 1516 대체)

UI의 "조건식 관리" 탭에서 파라미터를 편집해 새 버전으로 저장하고, "성과검증" 탭에서
그 버전을 실행하면 결과가 `data/condlab.duckdb`의 `bt_result`에 자동 기록된다.
콘솔에서 임시로 돌리지 말고 반드시 UI를 통해 버전을 남긴다.

조건식은 `cond_set(name, ver, params, bt, note)`, 결과는
`bt_result(run_at, name, ver, d_from, d_to, n_trades, up_rate, win_rate, avg_ret, ...)`.

### 확정된 사실 (2026-09-07 단일일 기준)

- 일봉용 `vol_mult`를 장중에 그대로 쓰면 안 된다. 누적거래량이 전일 총량의 1.5배를
	넘어야 하므로 오전 통과가 불가능하다(5건). 시각비례 `pace`로 바꾸면 21건이 되어
	키움 1516의 32건과 자리수가 맞는다.
- `require_prev_below`(전일 미돌파)는 장중 교차 기준에서 무의미하다. 켜든 끄든 21건.
	분봉이 base59를 상향 교차했다는 것이 이미 "오늘 그 아래에 있었음"을 함의한다.
- 1분봉에서 ±2~3%는 거의 반드시 먼저 터치되므로 익절·손절 폭이 결과를 지배한다.
	v2는 익절 5 / 손절 16 / 종가청산 0이었고, 장종료수익은 -0.28%인데 손절 적용 후
	평균은 -0.96%로 부호가 뒤집힌다.
- MFE 2.79% / MAE -2.75%가 대칭이므로 이 전략에 방향성 우위는 아직 없다.
- 처리속도는 하루 0.31초. 371일 전 구간도 2분 내에 끝난다.

### 미해결 과제

- 표본이 1일 21건뿐이다. 전 구간(2025-03-04~2026-09-07, 371일)으로 돌려야 결론이 난다.
- 손익 계산이 익절·손절 가격에 정확히 체결된다고 가정한다. 갭으로 뚫는 경우를
	반영하지 않아 손실이 과소평가된다. 체결가를 봉 종가로 바꾸는 옵션이 필요하다.
- 시장대비 수익률은 유니버스 등가중 평균이다. 실제 지수로 바꾸려면
	`market_index_minute_1m`의 컬럼 구성과 커버리지 확인이 필요하다(미확인).
- 관리종목·투자경고·거래정지 제외는 `market_instrument`에 플래그가 없어 재현 불가.
	`watchlist_daily`에 있을 가능성 미확인.
- 장중 교차 기준이라 시가부터 base59 위에서 출발한 갭상승 종목은 잡히지 않는다.
	1516의 "그 순간 조건 충족 상태" 기준과 다르다. `cross_only` 옵션 추가 검토.
